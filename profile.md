# Профиль подготовки

Обновлено: 2026-08-31

## Цель

- Минимальный результат: уверенный Middle+ .NET backend developer.
- Желаемый результат: демонстрировать отдельные Senior-сигналы и уверенно защищать решения.
- Рынок: российский бигтех; приоритет — банки и маркетплейсы уровня Сбера, Т-Банка, Ozon и Wildberries.
- Язык интервью: русский.
- Горизонт: 2–3 месяца.
- Долгосрочная подтверждённая нагрузка: 8 часов в неделю.
- Временный ускоренный режим: в дни 1–12 theory package примерно на 4 часа чистого изучения плюс 1.5–2.5 часа практики/опроса; дни 13–14 — итоговые mock. Ожидаемый общий объём цикла около 70–82 часов, затем возврат к адаптивному графику.

## Исходные данные кандидата

- Коммерческий опыт: 2 года.
- Backend: C#, .NET Framework 4.6.2, современные ASP.NET Web API проекты на .NET 8–10.
- Frontend: React, TypeScript/JavaScript.
- Предполагаемые знакомые области: async/await, GC, память и runtime.
- Сильные и слабые стороны пока не подтверждены независимыми заданиями.
- GitHub может быть предоставлен для отдельного разбора инженерных сигналов.

## Калибровка рынка

### Наблюдаемые требования

По репрезентативной выборке актуальных вакансий 2026 года:

- `must-have`: C#/.NET, ASP.NET Core/Web API, реляционные БД и SQL, PostgreSQL/EF Core или Dapper, тестирование.
- `must-have` для целевых high-load команд: диагностика и эксплуатация, производительность, надёжность, API и распределённые сбои.
- `differentiator`: Kafka/брокеры, Redis, gRPC, Docker/Kubernetes, observability, архитектурные решения.
- `differentiator` для Senior: high-load и 24/7 ownership, проектирование микросервисных взаимодействий, оптимизация и стабилизация, лидерство в решениях.
- `contextual`: MongoDB, ClickHouse, CQRS, event sourcing, конкретные Kubernetes-практики — зависят от команды.

### Выводы и допущения

- Указанные в вакансиях 3–4+ года — рыночный фильтр, но не доказательство грейда. При 2 годах опыта потребуется сильное независимое evidence по must-have доменам.
- Для Middle+ ожидается самостоятельная реализация и диагностика bounded-фичи.
- Для приближения к Senior нужны системные trade-offs, partial failure, данные/консистентность, rollout/rollback, observability и ownership.
- Алгоритмические секции конкретных компаний пока не калиброваны; уточнить по выбранным командам или вакансиям.
- Есть отдельный чат по алгоритмическим задачам; его переносимое состояние хранить в `algorithms.md`, не смешивая с backend evidence.

## Ограничения и риски

- Пока нет baseline по SQL/EF Core, тестированию, распределённым системам, эксплуатации и system design.
- Подтверждён пробел: есть практический опыт EF Core, но отсутствует системная база по SQL, PostgreSQL isolation/locking и анализу запросов.
- Самооценка runtime/async противоречива; требуется практическая проверка.
- Версии .NET 9/10 и framework-specific детали проверять по актуальной документации Microsoft при изучении.

## Interview execution preference

- На live coding кандидат намеренно проговаривает модель задачи, допущения, план, проверки и коррекции курса, чтобы интервьюер наблюдал reasoning process.
- Требуется тренировать структурированную narration без непрерывного потока сознания и без преждевременного coding.
